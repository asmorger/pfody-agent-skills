# Publishing without a yes

**Smell.** Tracker items created because the backlog was finished and publishing was obviously the
next step. Or on the strength of an earlier "yes, and then put them in the tracker" from before the
backlog existed. Or the item set was never shown — just a count: "created 1 Epic, 2 Features, 7
stories".

**Why it is wrong.** This is the skill's one irreversible step. Tracker items get assigned, reported
on and worked; a wrong set costs more to unpick than it cost to create, and some of it cannot be
unpicked. An inferred yes is also the wrong kind of permission: the person agreed to the idea of
publishing, not to these nineteen items with these parents, which is the thing they would have
caught.

**Instead.** Show the full set — every item with its level, title and parent — and get a clear yes in
the current conversation, with the status `accepted` and Gate 3 approved. Create parents before
children, read the items back, and record their ids. If no tracker tool is available, hand over the
backlog file and stop rather than improvising an import
([`../principles/only-a-person-crosses-a-gate.md`](../principles/only-a-person-crosses-a-gate.md),
[`../practices/publish-a-backlog.md`](../practices/publish-a-backlog.md)).
