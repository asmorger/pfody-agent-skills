# An orphan note

**Smell.** A rule note with an empty backlinks pane. A question nothing links to. A source note no
statement cites. Each is correct, well-formed, properly tagged — and reachable only by searching for
something you would have to already know.

**Why it is wrong.** In a graph of small notes the links *are* the structure; there is no document
order left to carry meaning. So an orphan is knowledge the record contains and cannot deliver: the
reader who needed it did not know to look, and the reader browsing from the home note never arrives.
Orphans also break the derived lists the vault depends on. A source note with no inbound links looks
like a source that changed nothing, when it may be the anchor for six rules whose authors cited it in
prose instead of in a property.

**Instead.** Link it in, in the direction that will be travelled. A new rule earns a mention from a
neighbouring rule's **Also** line and a `sources` property pointing at its source. A question is
linked from the rule it blocks. A fact is linked from the rule that depends on it. The MOCs catch
notes by type automatically, so an orphan after that is a note nobody could place — which usually
means it belongs to a topic that does not exist yet, and that is worth saying out loud
([`../principles/links-are-the-structure.md`](../principles/links-are-the-structure.md),
[`../references/bases.md`](../references/bases.md)).
