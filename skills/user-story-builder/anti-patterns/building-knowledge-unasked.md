# Building knowledge unasked

**Smell.** A request for one story from one conversation, answered by standing up a `Knowledge/` tree
with a source register, a business rules file and an open questions register. Or the knowledge
corpus built inside this skill, by hand, because delegating felt like a detour.

**Why it is wrong.** A knowledge system is a substantial, visible change to someone's project and an
ongoing commitment to maintain it — not a side effect of asking for a story. Building it unasked also
answers a question the user may have had a reason to decline: sometimes one story from one conversation
is exactly the right scope. Building it *here* is a different error: it duplicates a producer skill
badly, because reconciliation, authority ladders and change control are not story craft.

**Instead.** Offer the fork, only when the corpus is genuinely absent, and only as a fork: build
sourced knowledge first and reach Mode A, or proceed now in Mode B or C. On a yes, delegate to
`anchored-knowledge` or an equivalent builder and re-enter intake from discovery. With no builder
available, offer to scaffold a minimal source file instead. The handoff is one-way — invoke the
builder, never contain it
([`../principles/delegation-not-inclusion.md`](../principles/delegation-not-inclusion.md),
[`../practices/offer-to-build-knowledge-first.md`](../practices/offer-to-build-knowledge-first.md)).
